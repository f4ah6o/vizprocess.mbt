# 2026-05-10

## process workspace session store

今日は `vizprocess` に durable process workspace session store を追加する。
実装前に `packages/vizprocess` の manifest / process 実装を確認し、既存の
`VizProcess` を source of truth として snapshot projection を作る方針にした。

実装計画:

- `packages/vizprocess/session_store.mbt` を追加し、`workspace`、`manifest`、
  `resolvedSources`、`nodes`、`attachments`、`selection`、`preview`、
  `diagnostics`、`lastAction` に対応する型を定義する。
- dataset / chart / artifact の flat summary projection を public function として
  追加する。
- manifest parse / validation 後に snapshot を更新する規則を
  `refresh_manifest` に閉じ込める。valid の場合は derived topology を差し替え、
  invalid の場合は attachments と preview は維持しつつ stale な nodes を消す。
- `docs/architecture.md` に OPFS は target architecture ではなく reference
  implementation だと明記する。
- `moon fmt`、`moon check`、`moon test`、必要なら `just test-js` で確認する。

`durable` は「ブラウザのタブを閉じても再開できる永続的な状態」という意味で使っている。
今回の session store は OPFS 固有の key-value state ではなく、App Server が保持して
複数 client から同じ process を再開できる contract として扱う。

## App Server process tools

runtime 側に App Server process tool 境界を足した。実装前に
`ProcessWorkspaceSnapshot` を読み直し、既存の session store を source of truth にして、
tool は snapshot を受け取って更新後 snapshot と diagnostics を envelope で返す形にした。

実装計画:

- `packages/vizprocess/app_server_tools.mbt` に read-only、mutating、
  approval-required の access 区分と input / output 型を追加する。
- manifest replace、node upsert、attachment import、validate、render preview /
  persist を snapshot 更新関数として実装する。
- attachment removal と external destination 付き export は destructive / external
  side effect なので、実行せず approval proposal だけを返す。
- envelope JSON は key order を固定し、client が snapshot / diagnostics / preview /
  approval を安定して読めるようにする。
- `app_server_tools_wbtest.mbt` で manifest replace、validate、render、node upsert、
  attachment import、approval proposal を確認する。

`approval proposal` は「tool が危険な操作を勝手に実行せず、client や user が承認できる
構造化された提案だけを返す」ための contract として置いた。今回の runtime core では
HTTP や外部 storage connector は持たせず、App Server client が同じ workspace semantics
を使える境界だけを確定した。
